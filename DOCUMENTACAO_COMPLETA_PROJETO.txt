1. VISÃO GERAL E PROPÓSITO DO APLICATIVO
================================================================================
O FinFlow é uma solução completa de gestão financeira pessoal e empresarial leve,
projetada para operar em tempo real com sincronização entre múltiplos aparelhos
(computadores, tablets e smartphones) através do Firebase Firestore.

Principais Recursos do Sistema:
- **Painel Geral (Dashboard)**: Visão consolidada de Patrimônio Líquido, Saldo Total
  em Contas Bancárias, Faturas de Cartão de Crédito e Total Investido, além de
  gráficos analíticos de fluxo de caixa e alocação de gastos.
- **Contas Bancárias & Extrato Unificado**: Gerenciamento de múltiplas contas correntes,
  poupança e carteiras digitais, com histórico de transações, filtros e conciliação.
- **Cartões de Crédito & Faturas Parceladas**: Acompanhamento de limites, datas de
  fechamento/vencimento, projeção de faturas futuras e detalhamento de compras parceladas.
- **Carteira de Investimentos**: Gestão de Renda Fixa, Ações, FIIs, Fundos e Criptoativos
  com monitoramento de valor investido vs. valor atual e rentabilidade acumulada.
- **Contas a Pagar / Futuros Pagamentos**: Agendamento de contas e boletos com cálculo
  dinâmico de status ("Pendente" para atrasados, "Em Aberto" para a vencer) e liquidação
  bancária automatizada (débito instantâneo no extrato bancário).
- **Monitoramento Diário de Alertas**: Detecção proativa de contas com vencimento
  em menos de 3 dias, disparando alertas visuais com contagem regressiva e notificações.
- **Leitor Inteligente de Extratos com IA (Gemini API)**: OCR e processamento semântico
  de arquivos PDF, imagens e textos de extratos bancários e faturas, extraindo todas
  as transações com categorização automática.
- **Hub de Open Finance**: Painel de sincronização e status de integração bancária.
- **Autenticação Segura & Modo Administrador**: Gate obrigatório de acesso com suporte
  a Login Google, E-mail/Senha e Acesso Admin Master com usuário "admin" e senha "admin".
- **Exportação Multiformato**: Geração de relatórios em PDF auditados (jsPDF + AutoTable)
  e planilhas Excel estruturadas (XLSX).

4. ARQUITETURA BACKEND E API REST (server.ts)
================================================================================

O arquivo `server.ts` unifica o servidor da aplicação com as seguintes atribuições:

1. **Vite Middleware em Desenvolvimento**:
   Em ambiente local/dev (`process.env.NODE_ENV !== "production"`), o servidor executa
   o Vite como middleware Express (`appType: "spa"`), permitindo carregamento rápido
   e compilação de assets em tempo real. Em produção, serve os arquivos estáticos de `dist/`.

2. **Endpoint de Inteligência Artificial `/api/parse-statement`**:
   - **Método**: POST
   - **Parâmetros**: `rawText` (texto do extrato), `targetType` ('bank' | 'card' | 'investment'),
     `fileBase64` (arquivo codificado em Base64), `mimeType`, `fileName`.
   - **Segurança da Chave**: O `GEMINI_API_KEY` reside exclusivamente no servidor backend
     (`process.env.GEMINI_API_KEY`), nunca exposto no código do cliente.
   - **Modelo Utilizado**: `gemini-3.6-flash` via `@google/genai`.
   - **Schema Estruturado JSON**:
     Força a IA a responder em JSON estrito contendo:
     * `date`: String no formato "YYYY-MM-DD"
     * `description`: Nome limpo do estabelecimento
     * `amount`: Valor numérico da transação
     * `isExpense`: Booleano (true para débitos/compras, false para receitas)
     * `category`: Categoria padronizada
     * `type`: Tipo de operação ("PIX", "TED", "Boleto", "Cartão", etc.)
     * `currentInstallment` e `totalInstallments`: Controle de compras parceladas
     * `invoiceMonth`: Mês de competência da fatura (YYYY-MM)

3. **Endpoint de Verificação de Saúde `/api/health`**:
   - **Método**: GET
   - Retorna `{ status: "ok", geminiConfigured: boolean }`.

5. ARQUITETURA DE DADOS NA NUVEM (Firebase Firestore & Auth)
================================================================================

A. Estrutura de Coleções Firestore (Multi-Tenant por Usuário):
Os dados de cada usuário ficam isolados sob o seu identificador único (`userId`),
garantindo privacidade e conformidade com regras de segurança:

- `/users/{userId}`: Documento mestre do usuário com `email`, `displayName`, `role`,
  `hasInitializedData`, `lastSeededAt` e `updatedAt`.
- `/users/{userId}/accounts/{accountId}`: Contas bancárias do usuário.
- `/users/{userId}/bankTransactions/{transId}`: Transações bancárias e extrato unificado.
- `/users/{userId}/cards/{cardId}`: Cartões de crédito cadastrados.
- `/users/{userId}/cardTransactions/{transId}`: Compras e parcelas no cartão de crédito.
- `/users/{userId}/investments/{investId}`: Ativos financeiros da carteira.
- `/users/{userId}/investmentTransactions/{transId}`: Aportes e resgates de investimentos.
- `/users/{userId}/futurePayments/{paymentId}`: Contas a pagar e pagamentos futuros.
- `/users/{userId}/categories/{catId}`: Categorias personalizadas de receitas/despesas.
- `/users/{userId}/openFinance/{connId}`: Conexões bancárias do Open Finance.
- `/users/{userId}/devices/{deviceId}`: Dispositivos conectados do usuário.
- `/users/{userId}/notificationSettings/{docId}`: Preferências de alertas.
- `/users/{userId}/notificationLogs/{logId}`: Histórico de notificações disparadas.

B. Regras de Segurança Firestore (firestore.rules):
```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    function isSignedIn() {
      return request.auth != null;
    }
    function isOwner(userId) {
      return isSignedIn() && request.auth.uid == userId;
    }
    match /users/{userId} {
      allow read, write: if isOwner(userId);
      match /{subcollection}/{docId} {
        allow read, write: if isOwner(userId);
      }
    }
  }
}
```

C. Mecanismo de Sincronização e Prevenção de Sobrescrita:
1. Ao efetuar login, o sistema executa `checkAndSeedUserData`.
2. Essa função consulta o Firestore; se o usuário já possuir qualquer registro gravado
   na nuvem, o sistema **preserva integralmente a base existente** e não injeta dados de exemplo.
3. O hook `onSnapshot` estabelece canais de WebSocket seguros que atualizam o estado
   do React imediatamente sempre que qualquer alteração for feita em outro aparelho.

D. Autenticação e Modo Administrador Master:
- **Google Sign-In**: Login com um clique utilizando `signInWithPopup(auth, provider)`.
- **E-mail e Senha**: Cadastro e autenticação via `signInWithEmailAndPassword` e `createUserWithEmailAndPassword`.
- **Modo Administrador (`admin` / `admin`)**:
  Ao fornecer usuário "admin" e senha "admin", o sistema autentica a conta master
  `admin@finflow.app` (com provisionamento e fallback automático para autenticação anônima
  com role 'admin'), garantindo acesso imediato ao painel de administração.

7. REGRAS DE NEGÓCIO E FÓRMULAS DE CÁLCULO
================================================================================

1. **Regra de Status Dinâmico de Futuros Pagamentos**:
   - `today = new Date().toISOString().split('T')[0]` (Normalizado em YYYY-MM-DD).
   - Se `payment.status === 'Pago'`: Status definitivo é **Pago** (Badge Verde).
   - Se `payment.dueDate < today`: Status é **Pendente** (Vencido - Badge Vermelho).
   - Se `payment.dueDate >= today`: Status é **Em Aberto** (A Vencer - Badge Âmbar).

2. **Regra de Liquidação de Contas a Pagar**:
   - Quando o usuário clica em "Pagar / Liquidar Conta":
     a) Seleciona a data efetiva e a conta bancária debitada.
     b) Uma transação de débito com valor negativo (`-actualPaidAmount`) é criada no
        extrato da conta selecionada com a descrição `[Pago] + Descrição`.
     c) O saldo da conta bancária é reduzido imediatamente.
     d) O registro em `futurePayments` é atualizado para `status: 'Pago'` ou removido
        da fila de compromissos pendentes.

3. **Cálculo de Patrimônio Líquido**:
   - `Patrimônio Líquido = Total em Contas Bancárias + Total em Investimentos - Total de Faturas e Dívidas de Cartão`.

4. **Regras Visuais Obrigatórias (Destaque em Vermelho Negrito)**:
   - **Extratos Bancários**: Qualquer valor de débito/saída/despesa é formatado com
     `font-bold text-red-600 dark:text-red-500` e sinal negativo explícito (`- R$ ...`).
   - **Saldos Bancários Negativos**: Saldos finais com saldo devedor ou limite usado
     ficam em destaque vermelho negrito.
   - **Faturas de Cartão de Crédito**: As faturas abertas e parcelas futuras representam
     obrigações a pagar e são grafadas em vermelho negrito com sinal negativo.

5. **Sistema de Alertas Diários (< 3 Dias)**:
   - Para cada conta com `status !== 'Pago'`:
     `diffDays = Math.ceil((new Date(dueDate).getTime() - new Date(today).getTime()) / (1000 * 60 * 60 * 24))`
   - Se `diffDays <= 3`: A conta entra na lista de alertas urgentes, exibindo o sino
     notificador no cabeçalho e ativando o modal com contagem regressiva ("Vence hoje",
     "Vence em 1 dia", "Atrasada há X dias").

9. DESIGN SYSTEM, TEMA E DIRETRIZES VISUAIS (Anti-Slop)

  * Fundo Claro: `#f8fafc` (Slate 50) e `#ffffff` com bordas sutis `#e2e8f0`.

  * Alerta: Amber `#f59e0b` para contas a vencer e avisos.
  * Perigo / Débito: Rose `#e11d48` / Red `#dc2626` em negrito para despesas e saldos negativos.
- **Tipografia**:
  * Escala proporcional clara com legibilidade estrita (mínimo 14px em tabelas e 16px em textos).
  * Numerais monetários em fonte tabular monoespacada para alinhamento contábil perfeito.
- **Micro-Interações**:
  * Transições suaves de 150ms em hover e estados ativos.
  * Animações de entrada suaves via `motion` nos modais e alertas.

10. GUIA COMPLETO DE INSTALAÇÃO, CONFIGURAÇÃO E EXECUÇÃO

A. Pré-requisitos:
- Node.js versão 18 ou superior instalado.
- Gerenciador de pacotes npm, yarn ou bun.
- Projeto Firebase configurado com Firestore e Firebase Authentication ativados.
- Chave de API Google Gemini (Google AI Studio) opcional para extração inteligente via IA.

B. Passo a Passo de Execução Local:

1. Clonar ou extrair o projeto no seu computador:
   ```bash
   git clone <URL_DO_REPOSITORIO>
   cd gestao-financeira
   ```

2. Instalar todas as dependências:
   ```bash
   npm install
   ```

3. Configurar as variáveis de ambiente no arquivo `.env`:
   ```env
   GEMINI_API_KEY=sua_chave_gemini_aqui
   ```

4. Iniciar o servidor de desenvolvimento:
   ```bash
   npm run dev
   ```
   O aplicativo estará disponível em: `http://localhost:3000`

5. Gerar a build de produção otimizada:
   ```bash
   npm run build
   ```

6. Executar o servidor compilado em produção:
   ```bash
   npm start
   ```
